## Паспорт

- Зависимости: T03, T04.

- Исполнитель: Opus 5.5 / `bis-implementer`; ревью: `bis-reviewer` либо явно обозначенная самопроверка.
- При старте заполнить: base SHA, реальная ветка/worktree, владелец, test DB-файл/порты.
- При передаче заполнить: result SHA, команды и [отчёт](../reports/README.md).
- Общие правила: [CLAUDE.md](../../CLAUDE.md), [спецификация](../MVP_SPEC.md), [оркестрация](../../ORCHESTRATION.md).

## Цель

Создавать заказ с серверной фиксированной стоимостью, владельцем и защитой от повторных/конкурентных запросов.

## Область изменений

modules/rides/ модели, schemas, repository, service и creation/detail router; test cases; миграции. Сохранить pure pricing из T04.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. Сохранить quote с owner, метрами, секундами, геометрией, тарифом, KZT и expiry 5 минут; не держать транзакцию во время внешнего HTTP.
2. POST rides/quotes вызывает реальный адаптер; POST rides принимает quote_id и Idempotency-Key, не доверяет клиентской цене.
3. Создание включает атомарную проверку собственного непросроченного quote и не более одной активной поездки пассажира.
4. Полный набор состояний Ride из MVP_SPEC; optional driver_id и ограничения на принятые активные поездки водителя.
5. Idempotency scoped by user/operation; одинаковые key+payload возвращают один ride, несовпадение payload — 409.
6. GET ride доступен владельцу, назначенному водителю, admin; чужой ID не раскрывает детали.

## Сначала тесты: RED → GREEN → REFACTOR

- Цена/tariff snapshot, чужой/истёкший quote, попытка подмены суммы.
- Повторный key, тот же key с другим телом, одновременное создание одного/двух заказов.
- Запрет на чужую поездку, корректный начальный searching и отсутствие assignment до T06.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.

## Миграции

Quotes, rides, idempotency records, ограничения активных поездок. Одна ревизия/согласованная цепочка от принятой основы.

## Критерии приёмки

- [ ] Create/detail контракт работает, no duplicate ride при повторе/гонке.
- [ ] Активная поездка пассажира защищена БД, а не только if в Python.
- [ ] Сохранённые quote/ride не меняют цену при последующем изменении настройки тарифа.
- [ ] Транзакции и idempotency documented; миграции проходят обновление с данными.

## Проверки

Lint/types; unit/API/integration rides creation; реальные конкурентные транзакции на разных sessions; migration tests.

Указанные каталоги тестов — целевое расположение; при обоснованном уточнении записать реальные команды в отчёте. Команда, которая не запускалась, не отмечается как пройденная.

## Внешние зависимости

Live quote требует routing key. В тестах внедряется детерминированный адаптер, не глобальный обход production logic.
