## Цель

Предоставить будущему интерфейсу стабильные списки и историю без утечки чужих поездок и бесконтрольного admin CRUD.

## Область изменений

modules/rides/queries.py и read-router, modules/users/admin read-router, shared pagination по назначенному владению, тесты чтения.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. GET rides фильтруется по passenger/assigned driver; admin list доступен только admin.
2. Стабильная limit/offset пагинация с верхней границей, фильтр по состоянию и датам при необходимости.
3. Admin users/rides list возвращает разрешённые поля, без паролей, токенов и внутренних секретов.
4. Не выдавать всю историю координат; показывать только необходимые точки/время актуальности для доступного ride.
5. Не менять lifecycle/payment service параллельно T08; при желании отображать payment-поля дождаться принятого контракта.
6. Проверить разумное число SQL-запросов без N+1; индексы — под фактический query plan при обоснованной необходимости.

## Сначала тесты: RED → GREEN → REFACTOR

- User A никогда не видит rides User B; driver видит только свои assignment, admin доступ проверяется.
- Pagination bounds, deterministic order, empty list, repeated stable page.
- Ответы не содержат password hash/session cookie и скрытых данных профиля.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.
