# T04: Маршрутный адаптер и учебный тариф

## Паспорт

- Статус при подготовке: queued; актуальный статус ведётся в [очереди](../TASKS.md).
- Зависимости: T02.
- Плановая ветка: `task/t04-routing-pricing`.
- База: актуальный проверенный `integration/backend-mvp` после зависимостей.
- Исполнитель: Opus 5.5 / `bis-implementer`; ревью: `bis-reviewer` либо явно обозначенная самопроверка.
- При старте заполнить: base SHA, реальная ветка/worktree, владелец, test DB/порты/Compose project.
- При передаче заполнить: result SHA, команды и [отчёт](../reports/README.md).
- Общие правила: [CLAUDE.md](../../CLAUDE.md), [спецификация](../MVP_SPEC.md), [оркестрация](../../ORCHESTRATION.md).

## Цель

Получать дорожный маршрут через изолированный адаптер и точно рассчитывать серверную цену в KZT.

## Область изменений

modules/geo/, modules/rides/pricing.py как чистый расчёт, соответствующие unit/API tests. Не менять driver models, schema или общие auth fixtures параллельно T03.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. Подтвердить актуальный контракт openrouteservice Directions и реализовать RouteResult из MVP_SPEC через HTTPX AsyncClient.
2. API-key/base URL/timeouts через настройки; ключ не попадает в logs/errors. Обработать malformed responses, timeout, 429 и 5xx, ограничив повторы.
3. Чистая функция Decimal-тарифа edu-v1 с минимумом и ROUND_HALF_UP.
4. POST geo/route с авторизацией и валидацией координат. Отсутствие ключа — явная недоступность, не подставной маршрут.
5. Документировать тип геометрии, attribution/условия провайдера, если применимы. Не подключать платный тариф.
6. Подготовить отдельный opt-in smoke реального дорожного маршрута Алматы, без выполнения в каждом pytest.

## Сначала тесты: RED → GREEN → REFACTOR

- Тесты метрик, 10 км/25 мин = 2200 KZT, минимума, дробных входов и округления.
- Контрактные тесты provider adapter на 200/429/5xx/timeout/некорректную геометрию.
- Отсутствующий API-ключ не даёт fake 200; координаты представлены lon/lat.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.

## Миграции

Нет. Quote и его сохранение вводятся в T05.

## Критерии приёмки

- [ ] Детерминированные unit/adapter/API tests проходят без сетевого доступа.
- [ ] Код реального адаптера готов, провайдерские ошибки переводятся в предсказуемый контракт.
- [ ] Реальный маршрут проверен с ключом либо явно external_pending; прямое расстояние не выдаётся за дорожное.
- [ ] Нет миграций/фоновых сервисов и конфликтов владения с T03.

## Проверки

Lint/types; tests/unit/geo, tests/unit/rides/test_pricing.py, tests/api/geo; opt-in real-provider smoke только с ключом.

Указанные каталоги тестов — целевое расположение; при обоснованном уточнении записать реальные команды в отчёте. Команда, которая не запускалась, не отмечается как пройденная.

## Внешние зависимости

ROUTING_API_KEY для настоящего запроса. Его отсутствие не препятствует следующей реализации с тестовым RouteResult, но отмечается до финального показа.
