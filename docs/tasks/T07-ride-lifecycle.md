## Цель

Завершить корректный жизненный цикл поездки и защитить его от гонок с отменой и повторными командами.

## Область изменений

modules/rides/service.py, state/rules и command routers, history/audit models при необходимости; lifecycle tests.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. Реализовать arrive/start/complete/cancel/release по таблице состояний MVP_SPEC.
2. Проверять actor/ownership и текущее состояние атомарно; явные error codes для недопустимого перехода.
3. Отмена отзывает offer либо освобождает driver; driver release до начала перезапускает поиск, исключая этого водителя.
4. Complete освобождает водителя и фиксирует итог/время. Контракт для T08: добавление payment record после complete в той же бизнес-транзакции либо согласованным идемпотентным способом.
5. Сохранять историю переходов и причину cancel/release; не логировать избыточные координаты/секреты.
6. Одинаковая повторная завершённая команда имеет определённый результат; нельзя повторно начислить/создать поездку.

## Сначала тесты: RED → GREEN → REFACTOR

- Все разрешённые и запрещённые переходы; права пассажира, назначенного/чужого водителя/admin.
- Гонки accept vs cancel, start vs cancel, complete vs повторный complete.
- Driver release → новый поиск без повторного предложения этому же водителю.
- Терминальные состояния не оживают; stale driver location не завершает поездку автоматически.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.

## Миграции

История переходов/причин при необходимости; подтверждённую цепочку не переписывать.

## Критерии приёмки

- [ ] По API выполняется searching→assigned→arrived→in_progress→completed.
- [ ] Отмена и release согласованно освобождают все ресурсы; state/history не расходятся.
- [ ] Конкурентные тесты подтверждают сериализацию несовместимых команд.
- [ ] Подготовлен явный контракт completion для T08 без фальшивых платежей.

## Проверки

Lint/types; parameterized unit state tests; API commands; real DB race tests; migrations if changed.

Указанные каталоги тестов — целевое расположение; при обоснованном уточнении записать реальные команды в отчёте. Команда, которая не запускалась, не отмечается как пройденная.
