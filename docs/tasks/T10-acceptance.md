## Паспорт

- Статус при подготовке: queued; актуальный статус ведётся в [очереди](../TASKS.md).
- Зависимости: T08, T09.
- Плановая ветка: `task/t10-acceptance`.
- База: актуальный проверенный `integration/backend-mvp` после зависимостей.
- Исполнитель: Opus 5.5 / `bis-implementer`; ревью: `bis-reviewer` либо явно обозначенная самопроверка.
- При старте заполнить: base SHA, реальная ветка/worktree, владелец, test DB/порты/Compose project.
- При передаче заполнить: result SHA, команды и [отчёт](../reports/README.md).
- Общие правила: [CLAUDE.md](../../CLAUDE.md), [спецификация](../MVP_SPEC.md), [оркестрация](../../ORCHESTRATION.md).

## Цель

Передать реально запускаемый backend с воспроизводимым демонстрационным сценарием и честным отчётом для Astra.

## Область изменений

scripts/seed.py, seeds/, tests/e2e/, нужные migration/restart tests, README, docs/architecture.md, docs/reports/FINAL.md. Исправления приложения адресно по воспроизведённому дефекту.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. Повторяемый seed demo пассажира/admin/нескольких drivers и автомобилей. Явное окружение/пароль через локальную настройку; не удалять пользовательские данные по умолчанию.
2. Сквозной API сценарий: register/login → approved drivers/location → quote → search → reject/timeout → accept → arrive/start/complete → cash confirm → history.
3. Сценарий отмены/гонки, recovery после restart и платежного report без ложного confirmed.
4. Запуск из чистой копии/чистой БД, миграции с нуля и с предыдущей принятой схемы; отсутствие autogen diff и одна head.
5. README: точные install/run/migrate/seed/lint/type/test/demo команды; работа с cookie/CSRF; настройка внешних ключей; backup/restore; ограничения локального MVP.
6. Создать docs/architecture.md с ER/state схемами, dependency overview, единицами и ключевыми ADR; подготовить API handoff React.
7. Исправлять найденные ошибки по regression test-first; не переписывать архитектуру в финале.

## Сначала тесты: RED → GREEN → REFACTOR

- Новые E2E/acceptance assertions сначала демонстрируют отсутствующее поведение или конкретный баг, затем исправление.
- Если уже существующий сквозной тест сразу зелёный, честно записать regression/acceptance check без выдуманного исторического RED.
- Для seed проверить повторный запуск и отказ от опасного окружения до реализации соответствующей логики.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.

## Миграции

Новых предметных схем не планируется. Исправления выявленных дефектов — с отдельной проверенной ревизией при необходимости.

## Критерии приёмки

- [ ] Локальный полный набор lint/type/tests проходит; приложение воспроизводимо запускается по README.
- [ ] Seed повторяем, нет CI, неожиданных brokers и миграций при startup.
- [ ] Реальный provider smoke выполнен либо ясно external_pending; тестовые адаптеры не скрывают отсутствие ключей.
- [ ] FINAL содержит branch/SHA, запуск, итоги проверок, ссылки на task reports и конкретные оставшиеся зависимости.
- [ ] Реализация остаётся в integration/backend-mvp для Astra; main не обновлён автоматически.

## Проверки

Полные lint/types/pytest; docker compose config и чистый запуск; upgrade/check/heads на одноразовой БД; seed дважды; E2E; opt-in routing smoke при наличии ключа.

Указанные каталоги тестов — целевое расположение; при обоснованном уточнении записать реальные команды в отчёте. Команда, которая не запускалась, не отмечается как пройденная.

## Внешние зависимости

Реальный маршрутный ключ и Kaspi-ссылка, если ещё не переданы, явно перечисляются. Без ключа нельзя объявлять реальную маршрутную интеграцию полностью принятой.

## Передача

Передать точный SHA, список изменений, RED/GREEN, результаты проверок, миграции, ограничения и следующий шаг. Главная сессия выполняет ревью, интеграцию и обновляет `docs/TASKS.md`; исполнитель не объявляет сам себе приёмку.
