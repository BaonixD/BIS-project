## Цель

Обеспечить реальную регистрацию, вход, отзыв сессии и основу проверки прав.

## Область изменений

modules/auth/, modules/users/ базовая модель пользователя, auth tests, ревизия, security-конфигурация и ADR. Общая регистрация router — через координатора.

Общие файлы передаются одному владельцу; не редактировать их конкурентно. Нет права расширять задачу до фронтенда, CI или новой инфраструктуры.

## Реализация

1. Реализовать раздел 4 MVP_SPEC: нормализация username, безопасное хеширование пароля, роли passenger/driver без публичного admin.
2. Реализовать серверные сессии, expiry, HttpOnly cookie, logout revoke, доступ к /auth/session и документированный способ CSRF для будущего React.
3. Записать ADR про session/CSRF/Origin, local HTTP vs Secure cookies и конфигурацию CORS. Использовать стандартные библиотеки, не собственный алгоритм криптографии.
4. Ввести dependencies текущего пользователя и проверки роли без переноса HTTP-объектов в сервисы.
5. Добавить ограниченный перебор входа для локального одного процесса; описать reset при рестарте и bounded storage.
6. Подготовить отдельную локальную команду создания admin с паролем через безопасный ввод/окружение. Не коммитить постоянный admin пароль.

## Сначала тесты: RED → GREEN → REFACTOR

- Тесты регистрации, дубликатов с разным регистром, входа/неверного пароля, истечения и отзыва сессии.
- Тесты запрета admin signup, небезопасного Origin и мутаций без CSRF.
- Тесты нераскрытия password/session token и ограничителя попыток с контролируемым временем.

Для каждого нового поведения сохранить команду и содержательную причину RED, затем результат GREEN. После рефакторинга повторить затронутые проверки. Баг сначала воспроизводится тестом.

## Миграции

Таблицы пользователей и сессий; основание — фактический текущий Alembic head.

## Критерии приёмки

- [ ] HTTPX проходит register → login → session → защищённый запрос → logout → 401.
- [ ] Сессии в БД не содержат сырого cookie-токена; пароль не доступен в response/log.
- [ ] CSRF/Origin и роль защищены тестами, Swagger содержит понятный способ работы с сессией.
- [ ] Миграция работает с нуля и поверх T01; duplicate username защищён БД.

## Проверки

Общие lint/types; unit/api/integration auth tests; миграции upgrade/check на test DB; ручной HTTPX smoke без UI.

Указанные каталоги тестов — целевое расположение; при обоснованном уточнении записать реальные команды в отчёте. Команда, которая не запускалась, не отмечается как пройденная.

## Внешние зависимости
