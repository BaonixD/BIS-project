## Реализованное поведение

- `/api/v1`: `POST /auth/register` (passenger/driver; `admin` → 422), `POST /auth/login`, `POST /auth/logout`, `GET /auth/session`.
- Пароли — Argon2id (`argon2-cffi`), хеширование в потоке вне транзакции; неизвестный username проверяется против dummy-хеша; одинаковый ответ 401 `invalid_credentials`.
- Серверная сессия: случайный токен в HttpOnly cookie `taxi_session` (SameSite=Lax, Secure по `SESSION_COOKIE_SECURE`, 7 дней); в БД только SHA-256. Новый вход отзывает сессию из присланной cookie; logout — условный UPDATE `revoked_at`.
- CSRF: `X-CSRF-Token` этой сессии для всех методов, кроме GET/HEAD/OPTIONS; токен выдаёт `GET /auth/session` и login.
- Origin для login/register — allowlist `CORS_ALLOWED_ORIGINS` или собственный origin API; без Origin допускается. CORS с credentials без wildcard.
- Ограничитель входа: 5 попыток на нормализованный username за 900 с, bounded in-memory, сброс при успехе; 429 `too_many_attempts`.
- `CurrentUser`, `require_roles(...)`, общий `Clock` (`core/clock.py`, `ClockDep`), `SettingsDep`, `error_responses(...)` для OpenAPI.
- `scripts/create_admin.py`: пароль из `ADMIN_PASSWORD` или getpass, не в argv.
- ADR 0003, README «Аутентификация».
