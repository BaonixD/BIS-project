### Поведение

- `POST /api/v1/rides/{id}/arrive|start|complete` (назначенный водитель), `/cancel` (пассажир до `in_progress`, причина необязательна), `/release` (назначенный водитель на `assigned/arrived`, причина 1–200 символов). Одна транзакция: блокировка поездки → `Actor` из строки → `states.resolve_command` → `transitions.move_ride` (условный UPDATE, время этапа, событие). Повтор применённой команды — 200 без эффектов; посторонний — 404 раньше проверки повтора.
- Cancel отзывает pending (порядок rides → ride_offers), водитель сразу свободен, `driver_id` сохраняется как история. Release: `searching`, новое окно поиска, после коммита шаг поиска (сбой шага → 200 `searching`); освободивший водитель исключён.
- Времена этапов `assigned_at`, `arrived_at`, `started_at`, `completed_at`, `cancelled_at`, `cancel_reason`. Таблица `ride_events` для каждого перехода, включая системные `assign` (accept T06) и `mark_no_driver`.
- Accept по отменённой поездке — 409 `invalid_ride_transition`.
- Хук завершения `modules/rides/completion.py::on_ride_completed(session, ride, now)` — ровно один раз в транзакции complete; исключение откатывает завершение. Контракт для T08 часть B.
- `GET /rides/{id}` — карточка водителя (имя, телефон, машина, последняя координата и её время) только участникам при `assigned/arrived/in_progress`; устаревшая координата статус не меняет.
- Водитель на активной поездке: offline и `PATCH /drivers/me` → 409 `driver_on_active_ride`.
- ADR 0007, README «Жизненный цикл поездки».

### Ограничения

- PostgreSQL: проверка «водитель на активной поездке» при READ COMMITTED может не увидеть незакоммиченный accept (водитель уйдёт offline в момент принятия); двойного назначения нет. На SQLite записи сериализованы.
- Карточка водителя только в `GET /rides/{id}`; причина отмены и release — свободный текст; старые события не чистятся.
