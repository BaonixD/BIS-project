## Реализованное поведение

- `GET /api/v1/rides` (passenger, driver): пассажир — свои поездки, водитель — где он сейчас `rides.driver_id`; id зрителя подставляется из сессии и перекрывает фильтры; admin — 403 (у него `/admin/rides`).
- Фильтры: `status` (повторяемый), `created_from` включительно и `created_to` исключительно, только aware datetime; `from > to` → 422 `invalid_date_range`.
- `GET /api/v1/admin/rides` (те же фильтры + `passenger_id`, `driver_id`) и `GET /api/v1/admin/users` (id, username, role, created_at, display_name; фильтр role) — только admin, только чтение; `password_hash` не загружается.
- Все списки — `Page` (limit 1–100, по умолчанию 20; offset ≥ 0), порядок `created_at DESC, id DESC`, чтение через `read_transaction`. Элемент — краткая схема `RideSummary` без геометрии маршрута.
