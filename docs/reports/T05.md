## Реализованное поведение

- `POST /api/v1/rides/quotes` (passenger, CSRF): дорожный маршрут через провайдера вне транзакции, затем короткая транзакция; цена `edu-v1` в KZT; срок quote 5 минут по `Clock` (`now >= expires_at` — истёк). Ошибки маршрутизации проходят как 503/422, quote не создаётся.
- `POST /api/v1/rides` (passenger): тело только `{quote_id}`, обязательный `Idempotency-Key` (1–128 видимых ASCII; иначе 422 `idempotency_key_required` / `idempotency_key_invalid`). Одна транзакция: повтор с тем же телом → та же поездка, 201 и `Idempotent-Replayed: true`; другое тело → 409 `idempotency_key_reused`; чужой quote → 404 `quote_not_found`; использованный → 409 `quote_already_used`; истёкший → 409 `quote_expired`; активная поездка → 409 `active_ride_exists`. Поездка создаётся в `searching` со снимком маршрута и цены из quote. `IntegrityError` проигранной гонки разбирается по зафиксированным строкам; 500 не возникает.
- `GET /api/v1/rides/{id}`: пассажир, назначенный водитель, admin; остальным 404 `ride_not_found`.
- CORS: `Idempotency-Key` разрешён, `Idempotent-Replayed` открыт клиенту.
- ADR 0005, README «Поездки: quote и создание»; хелперы `tests/support/rides.py`, фикстура `ride_factory`.

## Ревью

Блокеров и should-fix нет. Передано в T06: полные индексы `rides(passenger_id, created_at)` и `rides(driver_id, created_at)` для истории; тест, сверяющий условия частичных индексов после `upgrade head` с моделью. Принятые мелочи: ответ при гонке выводится из состояния строк (на SQLite гонок нет — записи сериализованы); `gather`-тесты не доказывают пересечение транзакций; `can_view_ride` дублирует логику доступа `states.py`.

## Решение для владельца

Записывается только успешное создание поездки. Если первый запрос получил `409 active_ride_exists`, а прежняя поездка затем завершилась, повтор с тем же ключом создаст поездку (201). Строгое прочтение MVP_SPEC §6 («тот же ключ — тот же результат») требовало бы повторять и ошибку. Выбран более полезный для клиента вариант, описан в ADR 0005.

## Ограничения

PostgreSQL не проверялся; очистки старых quote и записей идемпотентности нет; реальный маршрут — external_pending.
