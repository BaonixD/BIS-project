# 0009. Лёгкая оплата: «Оплатил» без проверки

Статус: принято владельцем 3 ноября 2026 года. Заменяет [ADR 0004](0004-payments-cash-kaspi.md). Поток (способ и момент оплаты, «Оплатил») заменён [ADR 0010](0010-pay-before-order.md); правила ссылки Kaspi действуют.

## Контекст

ADR 0004 ввёл ручную сверку: `report` пассажира давал только `reported`, наличные подтверждал водитель или admin, Kaspi — admin с заметкой сверки, каждое изменение писалось в `payment_events`. Для учебного проекта это лишняя сложность: владелец выбрал простой поток, в котором пассажир сам отмечает оплату.

## Решение

**Методы и статусы.** Пассажир выбирает наличные (`cash`, по умолчанию) или ссылку Kaspi (`kaspi_link`). Статусы: `unpaid → paid`; время оплаты — `paid_at`. Нажатие «Оплатил» сразу засчитывает платёж. Подтверждения водителем или admin, статуса `reported`, заметки сверки, `verification` и журнала `payment_events` нет.

**Без проверки.** Реальных платежей и банковских API нет. Сервер не проверяет, что деньги пришли: `paid` означает только отметку пассажира.

**Ссылка Kaspi** — как в ADR 0004: только из `KASPI_PAYMENT_URL`, форма `https://pay.kaspi.kz/pay/<id>`, строгий хост `pay.kaspi.kz`, в Git не попадает. Сумма в ссылку не подставляется, покупатель вводит её сам. Пустое значение выключает Kaspi, наличные работают.

**Хранение.** `payments`: `id`, `ride_id` (`UNIQUE`), `amount_kzt` (`> 0`), `currency = 'KZT'`, `method`, `status`, `paid_at`, `created_at`, `updated_at`; CHECK: `paid` ⇔ задан `paid_at`. Миграция удаляет `payment_events` и колонки сверки (`verification`, `reported_at`, `confirmed_at`, `confirmed_by`, `confirmation_reference`), а статусы `reported` и `confirmed` переводит в `paid`.

**Открытие** не меняется: `complete` в той же транзакции создаёт `cash`/`unpaid` с суммой поездки; сбой откатывает завершение.

**API** `/api/v1/rides/{ride_id}/payment`:

| Маршрут | Кто | Правило |
| --- | --- | --- |
| `GET` | пассажир поездки, назначенный водитель, admin | `ride_id`, `amount_kzt`, `currency`, `method`, `status`, `paid_at`, `payment_url` (только у `kaspi_link`, иначе `null`) |
| `PUT /method` `{"method": "cash" \| "kaspi_link"}` | пассажир | только в `unpaid`, после — `409 invalid_payment_transition`; Kaspi без ссылки — `503 kaspi_unavailable`; тот же метод, пока `unpaid`, — `200` без изменений |
| `POST /pay` | пассажир | `unpaid → paid`; повтор — `200` с тем же ответом |

Порядок проверок: видимость (посторонний — `404 ride_not_found`), право роли (водитель и admin на команды — `403 payment_action_forbidden`), завершённость (`409 ride_not_completed`). `/report` и `/confirm` удалены. Команда блокирует `rides → payments`, конкурентные `pay` дают одну оплату.

## Последствия

- Поток фронтенда короче: complete → выбрать способ → открыть ссылку Kaspi → «Оплатил».
- Статус `paid` не доказывает получение денег. Это осознанное упрощение учебного MVP; тестовая отметка не выдаётся за реальный платёж.
- Аудит оплаты и данные сверки из ADR 0004 теряются при миграции; откат не восстанавливает удалённые события.
- Возвраты, эквайринг, webhooks и автоматическая сверка по-прежнему вне объёма.
