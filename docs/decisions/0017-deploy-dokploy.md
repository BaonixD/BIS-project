# ADR 0017 — Деплой одним контейнером в Dokploy

Дата: 24 ноября 2026. Решение владельца: учебный проект разворачивается на его Dokploy
(`panel.baonix.su`) самым простым способом, на SQLite. Уточняет
[ADR 0001](0001-sqlite-without-docker.md): локальная разработка по-прежнему без Docker
(кроме OSRM, [ADR 0014](0014-osrm-in-docker.md)), Docker используется только для деплоя.

## Решение

- Один репозиторий и один образ (`Dockerfile` в корне): собранный фронтенд и API отдаются
  одним процессом uvicorn на порту 8000. Один домен — HttpOnly-cookie входа и CSRF работают
  без междоменного CORS; Dokploy (Traefik) выдаёт HTTPS.
- `FRONTEND_DIST` включает раздачу сайта из FastAPI (`taxi_service/api/frontend.py`):
  клиентские маршруты получают `index.html`, `/api` и `/health` — никогда; `sw.js`,
  `index.html`, `precache.json` — `no-cache`, `/assets/*` — `immutable`.
- Данные — SQLite и PDF водителей — на постоянном томе `/data`. При старте контейнера
  `alembic upgrade head`, затем один worker (в процессе живут циклы назначения и ИИ-помощника).
- Маршруты на сервере — Mapbox (`ROUTING_PROVIDER=mapbox`); свой OSRM на сервере не
  поднимается: при сбое Mapbox запрос к недоступному OSRM просто завершится ошибкой маршрута.

## Почему не раздельные репозитории фронтенда и бэкенда

Проект временный и учебный: один репозиторий, одна сборка и одна выкладка проще в
поддержке, а OpenAPI-типы фронтенда генерируются из бэкенда в том же коммите.
