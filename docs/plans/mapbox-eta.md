# BIS Taxi — Mapbox ETA

Дата: 16 ноября 2026. Исправленный план по приложенному владельцем документу.
Статус: реализован и включён локально. Реальный запрос через API выполнен.
Отчёт: docs/reports/mapbox-eta.md. Полный тестовый прогон остановлен по последней
просьбе владельца; новые тесты больше не запускаются.

## Цель и исходное состояние

Основной routing сейчас OSRM, дополнительный — OpenRouteService. React/Vite,
Leaflet + MapLibre/OpenFreeMap; FastAPI и SQLite. Четыре тарифа, цена включает
длительность. Плашка прибытия уже находится над точкой назначения на карте.
Интеграция добавляет провайдер, не меняет дизайн и формулу тарифов.

## Контракт Mapbox

GET https://api.mapbox.com/directions/v5/mapbox/driving-traffic/{lon},{lat};{lon},{lat}
с geometries=geojson, overview=full, alternatives=false, steps=false.
Без будущего depart_at: расчёт на текущее время. MAPBOX_TOKEN — только серверный
SecretStr из .env, не VITE_*, не часть ошибок, логов, публичной конфигурации.

Основная длительность — duration. duration_typical — типичные условия с
историческим трафиком, а не свободная дорога. Данные live не гарантированы на
каждом участке: при их отсутствии Mapbox использует typical. Признак
traffic_mode=live_or_typical выставляется при наличии duration_typical; иначе
none. Подпись: «С учётом дорожной ситуации», без обещания именно текущих пробок.
Покрытие Казахстана заявлено Mapbox, точность конкретных поездок проверяется
отдельно. Не подгонять минуты коэффициентом.

## Backend

1. Добавить MapboxClient по существующему RoutingProvider. Повторно использовать
   bounded timeout/retry для 429/5xx/сетевых ошибок. 401/403 не повторять.
   NoRoute/NoSegment — route_not_found, без скрытого пересчёта у другого сервиса.
   Проверять finite/nonnegative метрики, GeoJSON и код ответа, не отражать
   message/URL внешнего сервиса в клиентской ошибке.
2. ROUTING_PROVIDER=mapbox выбирает Mapbox с резервным локальным OSRM.
   ORS остаётся отдельным поддержанным режимом. Fallback только при недоступности,
   отказе или невалидном ответе; его геометрия, метрики и provider все от OSRM.
3. Mapbox-режим оборачивается в короткий bounded cache (30 с, максимум 256
   маршрутов, точные координаты), совмещает параллельные одинаковые запросы.
   Ошибки не кэшируются; lifecycle отменяет незавершённые задачи. Резервному
   OSRM отдельный лимит 3 с после бюджета основного провайдера.
4. RouteResult дополняется traffic_mode, duration_typical_s и generated_at.
   Для старых ответов безопасные defaults: none/null/null. Три поля сохраняются
   одним routing_metadata JSON в ride_quotes и rides. Это обоснованная небольшая
   миграция: история должна сохранять происхождение прогноза. Старые маршруты
   не получают выдуманные пробки. ROUTE_SNAPSHOT_COLUMNS копирует метаданные.
5. Active ride estimate возвращает также route: метрики и геометрия одного
   расчёта. Снимок заказа и согласованная цена при обновлении ETA не меняются.
   Существующие проверки доступа, свежести геолокации и смены водителя остаются.

## Frontend и стоимость

1. Оставить плашку на карте, перевод RU/KK/EN. Для Mapbox показывать дорожные
   условия, для OSRM/ORS — «Без учёта актуальных пробок». До назначения явно
   «Если выехать сейчас», подача машины не включена.
2. Перед подтверждением проверить возраст quote. Если старше 60 с/истёк,
   получить новый quote, показать актуальные четыре цены и попросить нажать
   «Заказать» снова. Не создавать заказ и не открывать Kaspi по старой цене.
   Заказ с актуальным quote использует его фиксированный amount.
3. Запрос route идёт после окончательного выбора точек; движение карты само
   ничего не запрашивает. Разные координаты — разные query keys, старый ответ
   не подменяет новый. Не добавлять debounce там, где нет потока routing-запросов.
4. Active ETA общий query для карты и блока показателей, обновление раз в 60 с
   только во время assigned/in_progress; свежесть 90 с. Карта использует route
   этого же ответа, устаревшие/ошибочные прогнозы не объявляются актуальными.
5. Добавить атрибуцию Mapbox. Сохранить прокрутку тарифов, способ оплаты,
   идемпотентность заказа и все текущие экраны.

## Приёмка

В конце: unit HTTP adapter (включая секреты, ошибки и retry), cache/fallback,
API сохранения metadata quote→ride и неизменности цены после ETA, миграция на
старой SQLite и alembic check, frontend проверки подписи и обновления quote,
браузерная проверка формы/карты и заказа. Ruff, mypy, ESLint, tsc/build.
Реальные запросы: Индустриальная→MEGA, центр→SDU и аэропорт, несколько коротких
маршрутов при доступном токене. Фиксировать время проверки и результат, не
выдавать fake transport за реальный трафик. Сравнение с Яндексом — ориентир,
не истинное время поездки; для оценки ошибки нужны фактические поездки.

Перед локальной миграцией — резервная копия SQLite. Перезапустить API, проверить
readiness и геометрию/ETA из настоящего endpoint. Коммиты от Git-автора владельца,
без push до команды. Токен не коммитить. При недоступном токене готовый код и
проверки завершить, внешнюю точность отметить external_pending.
