# TulparTaxi — PWA: приложение из сайта

Дата: 24 ноября 2026. Статус: план, реализация не начата. Решение владельца: вместо нативного
приложения на Swift — PWA (сайт, который ставится на телефон как приложение); магазины приложений,
если понадобятся, — позже через Capacitor поверх этого же кода.

## 1. Что получим

- Иконка TulparTaxi на домашнем экране, запуск без адресной строки, своя заставка и цвет статус-бара.
- Быстрый повторный запуск: оболочка приложения (HTML, JS, CSS, шрифты, иконки) берётся из кэша.
- Понятный экран «Нет подключения» вместо белой страницы браузера.
- Подсказка «Установить приложение»: на Android — системная кнопка, на iPhone — короткая инструкция.
- Одна кодовая база для iPhone, Android и компьютера; всё, что уже сделано (тёмная тема, три языка,
  поддержка с ИИ, бонусы), работает как есть.

Чего PWA не даёт (и это нормально для учебного проекта):

- Геолокация водителя работает, пока приложение открыто на экране (так же, как сейчас на сайте).
  Фоновая геолокация — только в нативной обёртке (Capacitor, этап 4).
- Push-уведомления на iPhone — только если приложение установлено на домашний экран и iOS ≥ 16.4.
  Без push всё продолжает работать через опрос сервера, как сейчас.
- В App Store / Google Play PWA не публикуется (для этого — этап 4).

## 2. Обязательное условие: HTTPS и один домен

Service worker, установка и геолокация работают только по HTTPS (исключение — `localhost`).
Поэтому PWA по-настоящему проверяется только после деплоя. Рекомендуемая схема:

```
https://tulpartaxi.<домен>/          → собранный фронтенд (frontend/dist)
https://tulpartaxi.<домен>/api/...   → uvicorn (FastAPI) на 127.0.0.1:8000
https://tulpartaxi.<домен>/health/.. → uvicorn
```

Один домен для сайта и API важен: вход работает на HttpOnly-cookie с CSRF-токеном, и при одном
источнике не нужны сторонние cookie и сложный CORS.

Сервер (одна небольшая VPS, 2 ГБ RAM хватит):

- Обратный прокси с автоматическим сертификатом Let's Encrypt — проще всего **Caddy**
  (Nginx + certbot тоже подходит). Он отдаёт `frontend/dist` и проксирует `/api` и `/health`.
- `uvicorn --factory taxi_service.main:create_app` с **одним worker**: цикл назначения водителей
  и цикл ИИ-помощника живут в процессе, второй worker запустил бы их дважды.
- SQLite-файл и `private_uploads/` на диске сервера, ежедневная резервная копия обоих
  (`sqlite3 .backup`, не простое копирование из-за WAL).
- OSRM в Docker (как сейчас, `mem_limit: 1g`) или `ROUTING_PROVIDER=mapbox` с токеном —
  тогда Docker на сервере не нужен.
- `.env` сервера: `SESSION_COOKIE_SECURE=true`, `CORS_ALLOWED_ORIGINS=https://tulpartaxi.<домен>`,
  `DATABASE_URL`, `KASPI_PAYMENT_URL`, `GEMINI_API_KEY`, `MAPBOX_TOKEN`, `GOOGLE_CLIENT_ID`
  (если включаем вход через Google — в Google Console добавить домен в Authorized origins).
- Миграции перед запуском новой версии: `uv run alembic upgrade head`.

Внешние сервисы, которые на проде надо держать в рамках их правил:

- **Nominatim** (поиск адресов): не больше 1 запроса в секунду с одного клиента — уже соблюдается
  в браузере; найденные адреса теперь сохраняются на устройстве. Для большой нагрузки — свой
  геокодер или платный, но для учебного проекта достаточно.
- **OpenFreeMap** (тайлы карты): бесплатно, без ключа.
- **Gemini**: ключ только на сервере; при исчерпании квоты поддержка продолжает работать с оператором.

## 3. Этапы

### Этап 1. Устанавливаемое приложение (1–2 дня)

1. **Манифест** `frontend/public/manifest.webmanifest`:
   - `name: "TulparTaxi"`, `short_name: "TulparTaxi"`, `lang: "ru"`, `start_url: "/"`, `scope: "/"`,
     `display: "standalone"`, `orientation: "portrait"`;
   - `background_color` и `theme_color` — светлая тема (`#f6f6f6` / `#000000` для статус-бара
     с чёрной шапкой);
   - `id: "/"` — чтобы обновление манифеста не создавало «второе» приложение.
2. **Иконки** из `frontend/public/brand/tulpar-original.png` (круглый значок уже есть):
   192×192 и 512×512 (`purpose: any`), 512×512 `maskable` (эмблема в безопасной зоне 80 %,
   фон белый), `apple-touch-icon` 180×180 (уже есть). Скрипт генерации положить в `scripts/`.
3. **`index.html`**: `<link rel="manifest">`, `apple-mobile-web-app-capable`,
   `apple-mobile-web-app-title`, `apple-mobile-web-app-status-bar-style="black-translucent"`;
   `theme-color` с вариантами для светлой и тёмной темы (`media="(prefers-color-scheme: dark)"`).
4. **Заставки iOS** (`apple-touch-startup-image`) — по желанию; без них iOS показывает белый экран
   на долю секунды. Можно сгенерировать позже тем же скриптом.
5. Проверить вёрстку в режиме `standalone`: отступы под вырез уже учитываются
   (`env(safe-area-inset-*)`), нижняя навигация стоит над «полоской» iPhone.

Критерий готовности: Chrome DevTools → Application → Manifest без ошибок; на Android появляется
«Установить приложение», на iPhone «На экран „Домой“» даёт иконку TulparTaxi и запуск без адресной строки.

### Этап 2. Service worker и офлайн (1–2 дня)

Инструмент — `vite-plugin-pwa` (Workbox) с `registerType: "prompt"`; версию закрепить точно
в `package.json`.

Правила кэширования — главное здесь не навредить:

| Что | Стратегия | Почему |
| --- | --- | --- |
| Сборка (`index.html`, JS, CSS, шрифты, иконки) | precache | быстрый запуск, обновление по новой сборке |
| `/api/*`, `/health/*` | **только сеть, никогда не кэшировать** | заказы, оплата, статусы и чат должны быть свежими; ответы содержат личные данные |
| Тайлы и стиль карты (OpenFreeMap) | stale-while-revalidate, лимит ~200 записей / 7 дней | карта открывается быстрее, место ограничено |
| Nominatim | не кэшировать в SW | уже кэшируется приложением, правила сервиса |
| Kaspi, Google, Mapbox | не трогать | внешние платежи и вход |

- Навигационные запросы (`/`, `/history`, `/admin/...`) отдают `index.html` из кэша (SPA fallback),
  кроме `/api` и `/health`.
- Без сети приложение показывает экран «Нет подключения к интернету» с кнопкой «Повторить»
  (RU/KK/EN) — заказ без сети всё равно невозможен, важно не показывать пустую страницу.
- **Обновление версии**: когда вышла новая сборка, внизу появляется «Доступна новая версия —
  Обновить». Никаких тихих перезагрузок посреди поездки: во время активной поездки баннер ждёт.
- Проверить, что при выходе из аккаунта очищается кэш React Query; SW личных данных не хранит.

Критерий: Lighthouse → PWA «installable» и «offline» зелёные; включить «Offline» в DevTools —
приложение открывается и показывает экран без сети; новая сборка предлагает обновиться.

### Этап 3. Ощущение приложения (2–3 дня, по приоритету)

1. **Баннер установки**: Android — по событию `beforeinstallprompt` кнопка «Установить» в профиле
   и один раз на главной; iPhone (Safari, не установлено) — карточка «Поделиться → На экран
   „Домой“» с картинкой. Скрывать навсегда после закрытия (на устройстве).
2. **Push-уведомления** (Web Push, ключи VAPID на сервере): водителю — новый заказ, пассажиру —
   «Водитель найден» / «Водитель на месте», всем — ответ поддержки. Нужны: таблица подписок,
   endpoint подписки/отписки, отправка из уже существующих мест (назначение, ответ в поддержке),
   экран-запрос разрешения только после понятного действия пользователя. На iPhone работает
   только в установленном приложении.
3. **Wake Lock** для водителя на линии — экран не гаснет, пока приложение открыто
   (геолокация продолжает отправляться).
4. **Вибрация** при новом предложении заказа (Android; iOS не поддерживает).
5. **Shortcuts** в манифесте: «Заказать такси», «История», «Поддержка» — долгое нажатие на иконку.

### Этап 4 (если понадобятся магазины). Capacitor

Обернуть этот же `frontend/` в Capacitor: iOS- и Android-проекты, нативные плагины фоновой
геолокации и push. Для App Store нужен Apple Developer Program ($99/год) и Mac с Xcode;
для Google Play — разовый взнос $25. Код интерфейса не переписывается.

## 4. Проверка перед сдачей

- Lighthouse (мобильный профиль): PWA, Performance ≥ 80, Accessibility ≥ 90.
- Реальные устройства: iPhone (Safari → установка) и Android (Chrome → установка):
  вход, заказ, поиск водителя, поездка до конца, чат поддержки, тёмная тема, смена языка.
- Водитель в установленном приложении: выход на линию, получение предложения, геолокация.
- Без сети: открывается экран «Нет подключения»; после восстановления — работа продолжается.
- Обновление: выкладка новой сборки → баннер «Доступна новая версия» → обновление без потери входа.

## 5. Порядок работ

1. Деплой (раздел 2) — без HTTPS остальное не проверить.
2. Этап 1 → этап 2 → проверка на устройствах → этап 3 по приоритету.
3. Отчёт в `docs/reports/pwa.md`: что проверено на каких устройствах, результаты Lighthouse.
