# Mini Taxi Service — инструкции Claude Code

Ты исполняешь подготовленный Astra план разработки учебного backend MVP. Владелец проекта хочет Python/FastAPI, PostgreSQL/PostGIS, понятный модульный монолит и рабочий результат. Основной исполнитель — Opus 5.5.

## Начало сессии

1. Прочитай `CLAUDE_START.md`, `BACKEND_PLAN.md`, `ORCHESTRATION.md`.
2. Прочитай `docs/MVP_SPEC.md` и `docs/TASKS.md`.
3. Проверь `git status`, текущую ветку и историю; сохрани чужие изменения.
4. Прочитай текущую карточку и последний отчёт в `docs/reports/`, если работа уже начиналась.
5. При команде выполнять пакет начинай с первой доступной задачи, учитывая завершённые зависимости. Не создавай второй план вместо исполнения.

## Приоритеты

- Прямые уточнения пользователя имеют приоритет над файлами.
- `BACKEND_PLAN.md` хранит подтверждённые решения и инженерные ограничения.
- `docs/MVP_SPEC.md` конкретизирует контракты и явно обозначенные рабочие допущения оркестратора.
- `docs/TASKS.md` определяет зависимости; карточка ограничивает конкретную задачу.
- При противоречии исправь согласуемые документы; существенный продуктовый конфликт подними пользователю.

## Решения владельца от 3 ноября 2026

Имеют приоритет над остальным текстом пакета. Подробности: [docs/decisions/0001-sqlite-without-docker.md](docs/decisions/0001-sqlite-without-docker.md).

- Текущий этап работает на **SQLite** (SQLAlchemy async + aiosqlite), без PostgreSQL/PostGIS. Код остаётся переносимым на PostgreSQL/PostGIS: стандартные типы SQLAlchemy, ограничения и partial indexes с `sqlite_where` и `postgresql_where`.
- **Без Docker, Dockerfile и docker compose.** Приложение и тесты запускаются через `uv`.
- Ближайший водитель — геодезическое расстояние (haversine) с bounding-box предфильтром в SQL; детерминированный порядок сохраняется.
- Ссылка Kaspi получена и хранится в локальном `.env` как `KASPI_PAYMENT_URL`, в Git не попадает. Допустимый хост — `pay.kaspi.kz`.
- Оплата «как в такси» ([ADR 0010](docs/decisions/0010-pay-before-order.md)): способ (наличные или ссылка Kaspi) выбирается до заказа; Kaspi списывается (имитация) в момент назначения водителя, при отмене или `no_driver` после назначения — `refunded`; наличные после поездки подтверждает водитель. Без сверки и журнала событий.
- Четыре тарифа `economy/comfort/comfort_plus/business` (`edu-v2`, [ADR 0012](docs/decisions/0012-tariffs-and-car-classes.md)): quote отдаёт цены всех тарифов и `kaspi_payment_url`, заказ выбирает `tariff`; класс машины задаёт admin, предложение получает машина класса не ниже тарифа.
- Оценки после поездки ([ADR 0013](docs/decisions/0013-ride-ratings.md)): по одной на сторону, 1–5 звёзд, теги своей стороны, средний рейтинг в карточке водителя, предложении и профилях.
- Интерфейс — точь-в-точь по макету Figma `6VHeDBRKk6RWdTYqH0r66K` (фронтенд в `frontend/`).
- Пассажиры могут входить через Google ([ADR 0011](docs/decisions/0011-google-login.md)); Client ID владелец даст позже, до этого вход выключен.
- Не нагружать ноутбук: без нагрузочных тестов и высоких RPS; конкурентные тесты — с малым числом одновременных операций; не более двух одновременно работающих исполнителей.
- Коммиты частые и небольшие, от настроенной Git-идентичности владельца: отдельно RED-тесты, GREEN-реализация, рефакторинг и документация. Ветки задач сливаются в integration через `merge --no-ff`, без squash.

## Неподвижные границы

- Только бэкенд. React позже; мобильное приложение опционально.
- Локальный модульный монолит. Без CI, Kafka, микросервисов, Redis и Celery.
- Город Алматы, валюта KZT. Username/password; пассажиры — также Google (ADR 0011).
- Ближайший доступный водитель получает предложение на 30 секунд; затем следующий кандидат.
- Реальные дорожные маршруты через внешний сервис; движение разрешено симулировать.
- Наличные по умолчанию; Kaspi по предоставленной ссылке. Способ выбирается при заказе; списание и возврат Kaspi — учебная имитация без проверки, реальных платежей нет.
- Никаких покупок тарифов, реальных оплат, автоматического деплоя или выдуманных ключей.

## Test-first

Для каждого изменения поведения: напиши тест → запусти и проверь ожидаемое падение → реализуй → получи GREEN → рефакторинг с повторной проверкой. Regression-тест перед исправлением бага. Не ослабляй тест, чтобы скрыть ошибку.

RED должен объясняться отсутствием требуемого поведения, а не отсутствием зависимостей, БД или случайной ошибкой импорта. Минимальный каркас для сбора теста допустим. Сохраняй команды и результат в отчёте задачи. Для документации и инфраструктурного bootstrap используй нужные smoke-проверки без искусственных unit-тестов.

## Код

- `router → service` ([ADR 0008](docs/decisions/0008-functional-services.md)): сервисы — функции модуля с зависимостями через FastAPI `Depends`, SQL рядом в сервисе, без классов `*Service`/`*Repository`. Транзакцией владеет бизнес-функция; функции-запросы транзакцию не начинают. Роутер — один вызов сервиса и HTTP-ответ, без docstring.
- Отдельные сессии на конкурентные задачи. Ограничения БД дополняют проверки Python.
- Типизация, короткие функции, осмысленные имена, минимум комментариев.
- Схемы API отделены от ORM. Явные ошибки, права на конкретные объекты.
- `main.py` собирает приложение; миграции и seed — отдельные команды.
- Миграции проверяются вручную и на реальной SQLite-БД задачи (`render_as_batch`); совместимость с PostgreSQL сохраняется на уровне типов и ограничений.
- Без in-memory подмены, которая скрывает поведение файловой БД с несколькими соединениями, и без фиктивной успешной внешней интеграции.

## Работа и делегирование

- Главная сессия координирует очередь и интеграцию; исполнитель реализует отдельную карточку.
- При доступности используй `bis-implementer` и `bis-reviewer` из `.claude/agents/`.
- Убедись в фактической модели. Не подменяй Opus 5.5 молча и не запускай вложенные деревья исполнителей.
- На одну задачу — отдельная ветка/worktree и собственный файл тестовой SQLite-БД внутри worktree. Изолируй также порты при запуске API.
- Указывать `isolation: worktree` недостаточно: проверь фактические cwd и branch перед записью. При режиме agent teams явно обеспечь изоляцию; не допускай конкурентной записи в общий каталог.
- Сначала последовательный корректный проход. Разрешённые параллельные пары отмечены в `docs/TASKS.md`.
- Общие файлы, очередь и интеграционная цепочка миграций имеют одного владельца — главную сессию либо назначенного ею исполнителя.
- Собирай результат в `integration/backend-mvp`. Не сливай реализацию в `main` до итогового ревью Astra.
- Не публикуй реализацию и не создавай PR без отдельной команды. Локальные коммиты и merge в integration разрешены стартовым промптом.

## Непрерывность

- После задачи обнови очередь и сохрани `docs/reports/Txx.md`: SHA, RED/GREEN, проверки, ограничения и следующую задачу.
- Не останавливайся после первой карточки или одного коммита: переходи к следующей доступной задаче.
- Если один внешний ключ/ссылка отсутствует, отмечай только соответствующую проверку как `external_pending` и продолжай независимую работу.
- Не объявляй реальную маршрутизацию проверенной без реального запроса. Не выдавай тестовую оплату за настоящую.
- Не спрашивай повторно известные ответы. Технические детали в пределах плана решай самостоятельно и кратко документируй.
- После смены контекста возобновляй по Git, очереди и отчётам, а не по памяти.
